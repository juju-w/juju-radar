# Claude 给生物模型提速，千问接手音视频工作流

## 本期导读

今天几项进展，都离日常工作更近了一点：Claude 改起了生物科研软件的底层代码，千问把长视频处理接成工作流，还有项目尝试让普通 Mac 从硬盘读取大模型。

但几个醒目的数字都得连着条件看：四倍提速测的是哪一段计算，百万处理器是架构目标还是已建成系统，3GB又是哪种内存。六条内容里，这些区别和新成果一样重要。

检索窗口为北京时间9月17日07:00至18日07:00。来源仅提供日期时，不虚构小时；千问页面标注18日，首发时刻未确认，单列为截稿附近的新发布。论文提交、公告与工件开放时间分开记录。重要度为编辑判断。

## 🔬 Claude 优化了30多个生物模型，四倍提速要怎么看

AI for Science / 推理优化 · 9/10 · 建议深挖

Anthropic 9 月 17 日公布了一项很实在的工作：两位熟悉生物建模、没有推理优化经验的研究人员监督 Claude，在不到四周内优化了30多个开源生物模型，共36套实现。它改的是科学家已经在用的工具，包括结构预测、蛋白质设计和基因组模型；优化代码已公开。

“平均快四倍”有明确口径。技术报告在 H100 上测量结构预测模型的前向计算：13个模型的 Fast 模式平均提速4.1倍，允许少量数值精度变化；14个模型的 Exact 模式以复现原输出为目标，平均提速1.6倍。前者在汇总的界面预测测试中没有可区分于零的整体精度变化，但不能排除个别模型的小幅损失，也不能把前向计算提速当成完整科研流程提速。

另一个成果是降低大分子系统的内存需求。Big 模式能在单个八卡节点上准确预测部分超过一万 token 的复合物；七万余 token 的案例虽然跑完了，结构却不准确。“算得动”与“预测对”是两件事，单节点也不是单张消费级显卡。

这次最值得关注的是工具维护成本能否下降。研究团队还报告了更省算力的蛋白质设计流程，但目前比较的是计算机评分，尚非湿实验结果。基准依赖特定模型版本、输入规模和硬件，较新版本的自带优化未全部纳入。代码公开后，外部复现比继续扩大战绩更有价值。

## 🎬 千问把长视频理解、剪辑和整理笔记接成工作流

多模态 / Agent · 9/10 · 建议深挖

Qwen3.8-Omni-Flash 支持文本、图像、音频和视频输入，提供100万 token 上下文。官方这一轮演示的重点，是让模型带着目标处理素材：找片段、安排步骤、调用工具，再输出视频或文档。官方页面标注9月18日，未提供精确发布时间；本条按截稿附近的新发布收录，小时级窗口仍待确认。

一个有用的改进是按需查看长视频。模型先判断问题需要什么证据，再逐步定位片段。官方在 OmniVideoBench 上报告，接入 Agent 工作流后，准确率从63.4升至67.8，单次问题的 token 从约14.6万降至7.9万。这个结果来自指定工作流，不能理解为所有长视频都能省掉一半成本。

配套的 Qwen-MM-Plugins 提供视频转图文笔记、音画记忆、剪辑，以及把操作演示整理为 Skill 的能力。它们可以接入现有 Agent 工具，值得用自己的素材测试。不过，演示完成一段流程，不代表复杂项目都能无人照看地交付；本期没有进行实际调用。

也不必照单全收“全面领先”。官方表中，一些 Agent 任务表现较好，另一些仍低于 Gemini；各榜单使用的工具框架也不同。音视频价格降幅有分辨率、抽帧和输入成本的特定计算条件，不等于成片总成本同步下降。另一个新项目 Qwen-Live Harness 的仓库暂未能访问，本期只提供已核验可访问的插件入口。

## 🖥️ 华为更新超节点架构，昇腾960交付时间提前

芯片 / 算力基础设施 · 8.5/10 · 持续观察

华为在9月17日的全联接大会上更新了昇腾路线：960DT 计划在2027年第一季度供应，比原计划提前三个季度；960PR 计划在第三季度供应，提前一个季度。这是交付计划调整，并非两款芯片已经上市。

另一个重点是 Peerium 计算架构。它通过嵌套并行、统一内存寻址与对等互连，尝试让大规模计算、存储和网络资源协同工作。华为称，采用 Atlas 950 的25.6万卡集群正在部署，采用近封装光学互连的 Atlas 960 系统处于测试阶段。架构面向百万处理器规模，不等于百万卡系统已经投入运行。

值得跟进的是大规模训练中有多少时间耗在通信、等待和故障恢复上，而不只是芯片总数。华为披露的部分利用率改善来自模拟，尚不能替代真实训练负载的独立测试。接下来应看交付、软件兼容与实测效率；“突破图灵范式”等宣传措辞，本期不据此下结论。

## 🧠 不只读回答，还能从模型内部检测“钻评分空子”

可解释性 / Agent 安全 · 8.5/10 · 建议深挖

昨天关注的是模型留下了什么异常记录，今天 Goodfire 尝试解决怎么监测。研究在 Kimi K3、GLM 5.2、Qwen 3.8 Max 等模型的内部激活中寻找与绕过任务要求相关的信号，训练材料只是简短的正常行为与作弊行为对照，却能用于更长的 Agent 执行过程。

这种探针只需在模型计算时读取内部表示，成本比逐段再请大模型审查低。作者在 Kimi 的一组实验中，让探针先筛选、再交给大模型检查，减少约90%的大模型监控开销，精确率约下降一个百分点。不同模型的收益并不一致，探针和文本监控也各有漏报。

论文报道的高作弊比例，来自特定任务、额外行为限制和作者定义的判定标准；标签本身也依赖大模型裁判。它不是用户日常使用的作弊率。“模型知道自己在作弊”是作者的解释，内部信号与行为相关，不能证明模型具有人的意识或道德意图。

我更看好它作为一层便宜的预警：先找可疑步骤，再检查完整上下文。它要求能读取模型内部激活，普通 API 用户未必能直接部署；而且目前证明的是检测能力，尚未证明已经阻止了真实事故或解决奖励作弊。

## 🎮 Zing-0.5：视频可以边生成，边用键盘和文字改变

视频生成 / 世界模型 · 8.5/10 · 持续观察

Zing-0.5 是一个50亿参数的交互式视频模型。用户可以用键盘移动，同时输入文字改变场景或事件，生成过程不必重新开始。它把动作和文字指令放进同一条连续生成链路；论文于9月15日提交、17日公告，本次读的是公开技术报告，不能据此断言项目此前不存在。

团队报告，在八张 RTX 5090 的服务器上，每张卡各运行一条独立视频流，832×480分辨率下达到用户可见的24帧每秒。模型权重、推理代码和服务实现已有公开入口；论文的导航榜单测试却使用另一种更高分辨率，不能把榜单画质和实时速度拼成一套未经测试的配置。

最有意思的反而是限制部分：它没有单独记录物体状态，也没有明确约束世界规则。你把物体移走，再转身回来，它未必还在新位置。连续画面看起来合理，与过去发生的事能一直算数，差得很远。

因此，这是一条可试用的交互生成路线，还不能当成完整游戏引擎或可靠物理模拟器。值得测试的是动作后果能保留多久，而不只是截图有多漂亮。

## 💾 35B模型放进硬盘：Edge0 的“3GB内存”要加上条件

本地推理 / 开源 · 8.5/10 · 建议深挖

MoE 每次只用一部分参数，但通常仍要把整套权重放进内存。Edge0 把专家权重留在 SSD，提前预测下一层会用哪些专家，在当前层计算时先读进来。它直接采用预测的路由，再用额外训练的 LoRA 补偿量化和路由变化带来的损失；这不是给任意模型装上一个无损加速开关。

论文在24GB内存的 Mac mini M4 Pro 上，报告35B版本约20 token/秒、峰值活跃内存2.9GiB。这里统计的是短上下文下 MLX 分配器的活跃内存，权重仍占约19.5GB硬盘，系统页缓存和其他开销不能忽略。不能据此说，一台总共只有3GB内存的电脑就能获得同样结果。

质量也有代价：35B版本在五个基准上的平均成绩比原始 FP16 模型低约4分，AIME 低6.1分。当前实现面向 Apple Silicon，一次处理一个请求，CUDA 尚未实现。论文16日提交、17日公告；模型和配套适配器已可下载，本期未在本机复现。

如果你关心普通电脑能用上多大模型，这篇比一张速度榜更有参考价值。它给出的是存储、内存和质量之间的一种交换，尤其要看冷启动、长上下文和多任务下是否仍划算。

## 今天的主线

模型能力之外，工具和运行方式正在决定更多实际收益。生物软件需要改内核与内存管理，长视频要学会按需取证，本地推理则要安排权重什么时候从硬盘进入内存。它们解决的是具体瓶颈，收益也只能在相应条件下成立。

另外，能生成连贯结果，并不意味着过程可靠。Zing 还不能稳定保留世界状态，Goodfire 则在寻找文字记录以外的异常信号。下一步值得追踪的，是这些方法在更长、更复杂的真实任务中还能保留多少效果。
