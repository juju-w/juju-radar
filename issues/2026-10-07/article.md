# OpenAI放出722份数学稿件，Mistral开放新模型预览

<!-- reading-stats -->约 4,000 字 · 阅读约 14 分钟<!-- /reading-stats -->

Juju Radar · 2026 年 10 月 7 日

## 本期导读

OpenAI 今天一次公开了内部模型产生的大批数学手稿，附上部分可由计算机检查的证明。数字很惊人，但更值得看的是接下来谁来核对这些结果、怎样处理错误。Mistral 同日让 Large 4 进入公开 API 预览，以欧洲自建算力训练和服务一个万亿参数稀疏模型；权重还要等到月底。

另外三件事都与 AI 进入实际系统有关：OpenAI 的 Decisions API 开始公测，Google 放出可在端侧运行的图文音视频检索模型，Meta 和 Sierra 则想让商家认得出替用户办事的 Agent。最后补读一篇计算化学论文：Agent 改写了成熟的分子优化程序，目标很朴素——少做几次昂贵的计算。

## 🧮 OpenAI公开722份数学稿件，核验工作才刚开始

<!-- source-id: openai-math-collection -->

AI for Science / 数学 · 9.7/10 · 建议深挖

[OpenAI 公开了数学成果合集](https://openai.com/index/sharing-ai-progress-in-mathematics/)及其 [GitHub 仓库](https://github.com/openai/math)。仓库目前列出 722 篇手稿，归入 372 个结果家族；同一研究问题可能有主结果、补充论证和不同证明，因此不能把“722 篇”直接读成“722 个已经解决的公开难题”。OpenAI 还给出约 4000 道尝试过的问题、十份模型推理摘要和部分 Lean 形式化证明。Lean 能按明确的公理与规则检查写进去的推导步骤，但不是给整批论文盖上同行评审印章。

这次发布改变了问题的规模。过去谈“AI 做数学”，常常围绕一两道题和演示视频；现在研究者面对的是一整座可下载、可引用、会继续修订的手稿库。模型负责大量提出候选证明，数学界则要检查结果是否真是新发现、定理条件有没有写对、证明是否完整，以及同一结果是否已经存在于文献中。公开仓库还保留版本修订路径，让后续纠错有出处。这种生产与核验速度的不对称，可能比手稿总数更值得研究。

必须把成果状态说准。[仓库说明](https://github.com/openai/math)明确承认并非所有结果都配有 Lean 形式化，未形式化稿件可能有问题；公开的也不是产生它们的内部模型。OpenAI 给出的平均计算量约为每项三小时 ChatGPT Pro 等价推理，并不能据此推算每个结果的真实研究成本。今天可以确认的是材料已经开放供数学家检查，不能据此宣称其中每项重大猜想都已被学界接受。具体哪几项经得起审查，要靠逐篇后续工作回答。

## 🧠 Mistral Large 4开放预览：欧洲前沿模型开始争夺专业任务

<!-- source-id: mistral-large-4 -->

基础模型 / 多模态 · 9.2/10 · 建议深挖

[Mistral 发布 Large 4 的公开预览](https://mistral.ai/news/mistral-large-4/)：1 万亿总参数、每个 token 约 490 亿激活参数，原生支持多模态，API 今天已能试用。稀疏专家结构让模型容纳更多参数，却不必在每一步都调用全部参数；它仍有通信、内存和服务成本，不能只用“490 亿激活”估算实际部署价格。Mistral 称模型在欧洲自有数据中心用 3800 张 NVIDIA Grace Blackwell GPU 从头训练，服务预览版的也是这套基础设施。

它争夺的不是普通聊天分数。发布页重点展示编程 Agent、网络安全、法律、金融和视觉定位等专业任务，试图把模型能力、数据驻留和今后自部署放在同一张采购单上。对需要控制运行地点和安全策略的企业，欧洲训练与服务设施本身就是产品的一部分。Mistral 还把训练环境与其面向客户的 Forge 相连，说明它在尝试让企业任务进入模型改进循环。

目前的能力结论仍要克制：这些任务成绩主要由 Mistral 给出，不同测试的推理预算、拒答策略和工具条件未必一致。它自报 Terminal-Bench 4.0 为 28.3%，也不足以支持“所有编程任务领先”。[官方更新记录](https://docs.mistral.ai/resources/changelogs)确认今天开放的是 API 公测；权重、完整后训练方法和更多评测计划月底发布。到那时，外界才有条件测它在自有硬件上的真实吞吐、成本与安全表现。

## 🎯 OpenAI Decisions API公测：把高频判断从长回答里拆出来

<!-- source-id: openai-decisions-beta -->

决策模型 / Agent基础设施 · 9.0/10 · 建议试用验证

OpenAI 在 9 月开发者大会已介绍 Decisions API；[10 月 6 日的开发者公告](https://community.openai.com/t/decisions-api-is-now-available-in-public-beta/1403877)和[接口文档](https://developers.openai.com/api/docs/guides/decisions)确认它现在进入公开测试。调用者给它文本或图片，再预先写好问题和合法答案。接口可以返回某个条件成立的概率、从固定选项中选一个，或按有序等级给分。当前底层只支持 GPT-6 Luna。

它针对的是程序里反复出现的小判断：一张退货照片是否有损坏、一段消息该交给哪个部门、Agent 下一步该用哪个工具。传统做法会让聊天模型生成解释，再从文本里解析出答案；专用端点直接交付程序能消费的结果。OpenAI 称相对于 Luna 的 Responses API 最多快十倍。对要在一条流程里作几十次选择的应用，减少每次等待，可能比把单次回答写得更长更有用。昨天写过 Liquid d1 的视觉判断；两家公司都瞄准这一步，但仅凭接口形式不能断言底层模型采用相同架构。

也要分清它与通用“结构化输出”的任务边界。Decisions 适合答案事先列得出来的判断；要抽取任意字段或写解释，OpenAI 自己仍建议用 Responses API。速度数字是厂商相对自家接口的比较，返回的概率在具体业务数据上是否校准、错误会不会集中在罕见情况，都需要开发者复测。今天真正新增的是开发者可以开始对自己的判断任务测，而不只是看发布会演示。

## 🔎 Google把图文音视频放进一个可本地运行的检索模型

<!-- source-id: embeddinggemma-2 -->

开源模型 / 多模态检索 · 8.8/10 · 建议动手验证

[Google 发布 EmbeddingGemma 2](https://blog.google/innovation-and-ai/technology/developers-tools/embeddinggemma-2/)并[开放权重](https://huggingface.co/google/embeddinggemma-2)。它把文字、代码、图片、视频和音频都映射到同一个 768 维向量空间。所谓“嵌入”，是把内容变成可比较的数字坐标：用户输入一句“找那段讲雨天跑步的视频”，系统可以按语义相似度检索视频片段，而不必先给每帧写文字说明。这个模型输出的是用于检索的向量，不是直接回答问题的聊天模型。

更实用的是它把编码器做成可选模块。完整模型 7.4 亿参数；只处理文字时可只载入约 2.7 亿参数，需要图像或音频再加相应部分。Google 在 Pixel 11 Pro 上报告量化后纯文本活动内存约 191MB、全模态约 567MB，还允许把 768 维向量截到 512、256 或 128 维，降低本地索引占用。权重以 Apache 2.0 发布，开发者现在就能在私有相册、语音笔记或代码库上测试离线检索，而不用把原始资料都上传云端。

它不是把任何媒体“一压缩就懂了”。官方的代码检索和多模态基准仍需在真实中文材料、长视频和不同设备上复测；[模型卡](https://huggingface.co/google/embeddinggemma-2)特别提示，截到 128 维会明显伤及部分多模态质量，直接用 float16 还可能产生 NaN 或不易察觉的劣化。部署时应先量自己的召回率和内存，而不是照搬厂商单台手机的数字。

## 🔐 Meta与Sierra提议给个人Agent建立商家授权通道

<!-- source-id: personal-agent-protocol -->

Agent协议 / 公司战略 · 8.5/10 · 持续观察

[Sierra 宣布与 Meta 等公司共建 Personal Agent Protocol](https://sierra.ai/uk/blog/introducing-personal-agent-protocol)。参与方还包括 Shopify、Stripe、Walmart 等商家与支付平台。它要处理一个具体难题：当个人 Agent 替用户查订单、改航班或退货时，商家如何知道它代表谁、获得了哪些权限，以及该走网页、API 还是商家的客服 Agent？今天许多 Agent 仍像人一样点网页，身份与授权常常藏在登录状态里。

提议中的流程从商家网站发现可用服务开始，再建立基于 OAuth 的会话。用户可授予只读或写入权限，商家决定开放哪些操作、让 Agent 从哪种接口进入；同一会话可跨网页、API 和商家 Agent 延续。若真能互通，查商品库存和修改已付款订单就不必共用一个含糊的“能登录”权限。对企业来说，这也把代理流量从难辨认的模拟点击，变成有机会单独审计、限制与撤销的访问。

但今天公布的是合作方向，**不是已经部署的通用协议**。Sierra 说 v0.1 规范和参考实现本月稍后才发布。具体权限粒度、撤权后如何中断进行中的动作、支付与跨站场景怎样防冒用，都还没有可供外界审查的实现。名单里有大公司，代表共同参与设计，不代表它们的系统现在已按该协议互通。

## 🧪 近期补看：Agent改写分子优化器，少算昂贵的受力步骤

<!-- source-id: autosella -->

AI for Science / 论文与代码 · 8.3/10 · 建议读论文

这篇[分子几何优化论文](https://arxiv.org/abs/2610.06577)在北京时间 10 月 5 日深夜提交，比本期检索窗口早约七小时，因此列为近期补看。分子计算需要反复调整原子位置，直到能量降下来；在密度泛函理论计算中，每次求原子所受的力都很昂贵。作者没有让大模型直接预测“最好的分子”，而是让多个 Agent 改写成熟优化器 Sella 的代码，寻找能用更少受力调用完成同一目标的算法。

这里真正有意思的是筛选方式。候选程序如果靠过早停机来“省次数”，或者只对开发时见过的分子有效，就过不了准入门；留下的实现再换到未见分子和其他计算势函数上测试。作者报告，在 r2SCAN-3c 这一密度泛函设置下，表现最好的版本达到同等能量下降所需的受力调用数是原 Sella 的 40.2%—77.2%。[代码仓库](https://github.com/vdeshchenya/autosella)公开了冻结的优化器、基线、环境锁文件和评估分支，给别人复跑留了入口。

这不是“计算化学提速六成”的通用结论：比例指受力调用次数，实际壁钟时间还取决于每次计算、算法自身开销与硬件；结果也来自作者实验。它值得读，是因为把 Agent 写算法从好看的代码片段，落到了一个昂贵、可计数、可在留出分子上检验的科学计算步骤。若独立复测成立，这比只让 Agent 总结化学论文更接近实际科研工具。

## 今天的主线

今天最值得留意的，不是又有多少参数。OpenAI 的数学合集说明，模型已经能以远超人工阅读的速度制造研究候选；AutoSella 则把 Agent 改代码的进展压到“同样能量下降需要多少次受力计算”这个可检验指标上。产出越来越便宜，判断哪些结果可信、哪些改进能迁移，反而更费功夫。

另一侧，Decisions API 和 EmbeddingGemma 2 都在缩短工作流里的高频小步骤：一个把固定候选判断做成专门调用，一个让不同媒体在本地直接比较。个人 Agent 真要跨企业替人办事，Meta 和 Sierra 提出的身份与权限层又成为另一道门槛。模型会做事、程序能快速判断、商家愿意放行，是三件不同的事。
